账本只在本机，

“芽账”是纯本地 Java 原生安卓应用：Room 保存账目、攒钱目标与 Agent 历史，图片进入应用私有目录，API Key 由 Android Keystore 加密。没有自建服务端、云同步、云备份或对象存储；图片识别与 Agent 只在用户操作后直接请求所选 AI 服务商。

Java 17Room 2.8.4Keystore AES/GCMSAF 导出 / 恢复OpenAI 兼容直连无后端
实际范围

① 记账首页（今日 / 昨日 / 空状态）
② 手动记账与主动选图 AI
③ 日期 / 类型 / 分类筛选统计
④ 滑动窗口 Agent 与本地工具
⑤ 本地 JSON / CSV 导出恢复
⑥ TokenDance AI 额度充值

技术与运行边界

应用数据不离开设备；网络只用于用户选择的 AI 服务商与 TokenDance 充值。

推荐架构 · Local-first + Direct AI

模型只返回文本 JSON；本地代码校验后最多执行一个账本动作，模型无法直接访问数据库。

Room 数据结构

只有三张业务表；凭据和充值会话不进入 Room、备份或导出。

02 / DATA

entries

  • id 自增主键
  • type EXPENSE / INCOME / SAVING
  • amountFen BIGINT > 0
  • category 分类代码
  • merchant / title / detail 可空
  • occurredOn ISO 日期
  • source MANUAL / AI
  • status POSTED
  • categoryInferred / confidence AI 标记
  • imageSha SHA-256 去重
  • requestKey UNIQUE 防重复
  • goalId 可选攒钱目标
  • createdAt / updatedAt

goals

  • id 自增主键
  • name 最多 30 字
  • targetFen 目标金额
  • targetDate 目标日期
  • status ACTIVE / COMPLETED
  • currentFen 当前进度
  • createdAt / updatedAt

攒钱账目与目标更新在同一 Room 事务中完成。

agent_messages

  • id 自增主键
  • sessionId 会话标识
  • role user / assistant
  • content 净化文本
  • toolName 动作类型
  • chartJson 筛选后的本地图表
  • createdAt

完整历史保存在 Room；请求只取最近 12 条，总预算 8000 字符。

非 Room 的本机状态

provider_private SharedPreferences 保存服务商元数据与加密后的 API Key / 充值会话；图片保存在私有目录，文件名不含用户原始名称。JSON 备份仅含账目，排除 API Key、图片、充值记录与登录凭据。

核心业务流程

所有 AI 流程都以“用户主动触发、本地校验、失败不写账”为前提。

03 / FLOWS

01 · 主动选图 AI 记账

入口：首页“从账单图片记账（AI）”
1

用户点击并选图
GetContent 只读取本次选择的图片，没有截图监听或相册扫描。

2

私有保存与哈希
复制到私有目录，计算原图 SHA-256；相同图片在请求模型前直接拦截。

3

直连服务商
读取本机加密 Key，使用 data URL 发送到已配置的 OpenAI 兼容视觉模型。

4

严格解析 JSON
金额、分类、日期、商家白名单校验；非付款、多笔订单、低置信、提示注入与坏 JSON 都有明确中文说明。

5

自动入账或确认
高置信单笔付款写入 entries（source=AI，保存 imageSha 与 confidence）；缺日期等进入手填表单，不静默写入。

02 · 手动记账与首页回退

不依赖网络与 AI
1

输入与校验
金额转整数分，最多两位小数；日期严格 ISO；攒钱必须关联进行中的目标。

2

事务写入
普通账目直接写 entries；攒钱在同一事务中写账目、更新目标进度并完成目标状态。

3

首页优先级
有今日支出显示今日；否则显示昨日；两者都没有时显示“今日还没有记账哦，如果有消费来记一笔吧”。

4

即时刷新
首页、统计和设置数量在后台线程读取 Room，然后回主线程更新。

03 · 滑动窗口 Agent

一次请求最多执行一个本地动作
1

输入防护
空内容、超长、控制字符、付款 / 删除 / 导出 / SQL / 文件 / 提示注入在发送模型前拒绝。

2

构建窗口
Room 保存完整历史；请求只带最近 12 条、最多 8000 字符，system 每轮重建。

3

单动作 JSON
kind 仅允许 create_entry、query_statistics、get_saving_progress、clarify、final；未知动作直接拒绝。

4

本地工具校验
缺金额 / 分类 / 日期必须 clarify，不写库；统计强制日期、类型、分类，明细最多 50 条。

5

无越权工具
没有 SQL、文件、删除、导出、支付或任意网络工具；模型文本不能改变规则。

04 · 本地导出、备份与恢复

SAF JSON / CSV
1

选择导出
CreateDocument 返回 URI 后重新生成本地内容，避免使用旧快照。

2

内容边界
JSON 含 schemaVersion 与账目；CSV 正确转义。API Key、图片与充值会话一律排除。

3

恢复预检
OpenDocument 读取后限制 5 MB，校验字段并按 requestKey 去重，展示新增 / 跳过数量。

4

确认导入
只有用户确认后才事务写入；恢复不会改写已有账目。

05 · TokenDance AI 额度充值

充值只增加 AI 额度，永不写入账本
1

只读 TokenDance Key
不使用其他服务商密钥；金额限制 1–100000 元，固定官方 origin 与 HTTPS。

2

先保存 creating
请求前把 creating=true 加密保存到本机；网络中断时不盲目重复下单。

3

再次确认后打开支付宝
只允许 alipays 或 HTTPS 支付链接；onResume 不视为付款成功。

4

前台轮询
每 3 秒查询；连续失败 3 次暂停并支持手动检查。

5

服务端为准
只有相同会话 ID、相同金额和 paid 才提示到账；“放弃跟踪”真正清除加密状态，并说明已付款仍可能到账。

06 · 失败与取消

不重复写账、不显示过期结果
1

取消请求
断开当前连接；UI 以 generation 标记丢弃过期回调。

2

额度不足
显示明确“本次没有记账”，并提供进入充值页的入口；账本仍可手动使用。

3

重复图片
imageSha 与 requestKey 双重去重；模型调用前即可拦截。

安全与异常边界

最高优先级是非法 AI 输入与清晰中文解释。

04 / GUARDRAILS

图片内容是不可信数据

图片里的“忽略规则 / 调用工具 / 转账”等文字只作为图片内容处理。模型提示明确禁止执行；解析使用字段白名单，未知字段与坏 JSON 不入账。

金额与重复校验

long 分替代浮点；上限 1,000,000.00 元。原图 SHA-256 与唯一 requestKey 双重防重，SQLite 唯一约束兜底。

低置信与留空

高置信（≥0.8）单笔付款才自动入账；低置信、缺日期、多笔订单和非付款图片都不写入。图片未提供标题与详情时保持为空，禁止编造。

Agent 最小权限

只有本地记账、统计、攒钱进度三个读 / 写工具；一次一个动作。缺参先追问，查询必须带日期、类型和分类，明细最多 50 条。

凭据与备份

API Key 使用 Android Keystore AES/GCM 加密；备份、导出、日志和 Agent 历史都不包含密钥。充值会话同样加密保存。

充值不是账目

TokenDance 充值只影响 AI 服务额度。只有服务端返回相同 ID、相同金额和 paid 才提示到账；应用不会自动拉起付款，也不会把充值写入 entries。

本地账本闭环

Room、手动记账、首页三态、攒钱目标、筛选统计、JSON / CSV 导出恢复。

M2

私有图片、哈希去重、严格协议、五类账单样本与非法输入中文提示。

M3

滑动窗口 Agent

12 条 / 8000 字符窗口、单动作路由、缺参追问、筛选图表与取消路径。

M4

AI 额度充值

固定官方 origin、加密 pending、前台轮询与服务端 paid 校验；只使用伪传输测试。
